## 4月2日 - 文档编码转换

### 问题

- 想批量转换文档编码
- 豆包给的PowerShell命令，转换后内容可能变乱码
- 换了Python脚本，不行，电脑不支持
- VS Code脚本也不行，内容全部空白
- iconv尝试，没成

### 多种方案尝试

- 按住Shift+右键打开PowerShell执行命令
- PowerShell脚本：创建文本、填内容、修改名称、双击执行
- 都一样：ANSI转UTF-8会乱码，或转成带BOM的UTF-8

### 编码转换助手的坑

- 豆包推荐的软件一开始下载成360流氓软件
- 下载了编码批量转换助手，试用后还是转成带BOM的UTF-8
- 新版本高级选项点不了，需要付费

### 最终结论

- 到目前为止没有嵌入模型能识别ANSI编码的TXT文档
- 带BOM的UTF-8编码向量化会存在前后文字小部分丢失
- 解决方案分两步：先转带BOM的UTF-8，再转不带BOM的UTF-8

### 收获

- 数据清洗包含的内容有多重要
- 花半天掌握了TXT文档编码转换技能
- 不甘心，但最终还是有结果

## 4月30日 - RAG本质思考

### RAG的三要素

RAG本质上是在数据、Embedding跟Prompt之间做一个平衡点，或者根据不同业务场景做某一方面的权衡。

### 数据质量

- 什么样的数据产出什么样的结果
- 同一文档内的数据是否协调？是否准确？
- 另一文档的数据会不会有冲突？
- 在数以万计的字符内找出重点并提炼，就像在一眼望不到边的沙漠寻找绿洲

### Embedding策略

- Chunk size的大小以及重叠的大小，直接决定召回率和准确率
- 选择合适的嵌入模型至关重要
- 一个包含中文跟英文数据的知识库最优选只能是BGE-M3
- 也可以创建不同知识库，用不同嵌入模型

### Prompt调优

- 直接影响生成效果
- 幻觉率有多少？准确率有多少？
- Topk要设置多少？
- 检索方式是向量检索还是全文检索？亦或是混合检索？

### 关键工具

- Reranker使用会极大提升检索效果

### 总结

RAG是什么？依我拙见，是一个人站在三岔路口，每条路看起来都很好，但每条路都得尝试去走，走完之后要去开阔一条自己的路。

## 5月9日 - RAG调优进展

### 可用RAG的标准

- **召回率20%以内**：问10个问题，两个没有回复，可以接受
- **准确率80%以上**：问10个问题，只有两个没答对，可以接受
- **幻觉率20%以内**：问10个问题，只有两个出现偏差，可以接受
- **完整性70%以上**：问10个问题，只有3个没答对或答对一半，可以接受

### 纯RAG的局限

- 召回率百分百很容易：不导入信息，不加任何Prompt，召回率肯定百分百
- 但召回率百分百了，怎么解决幻觉、准确率和完整性？
- 纯RAG不管怎么调优都很难达到理想效果
- 除非数据不多，并且有固定的提问方式

### ChatFlow尝试

#### 第一次尝试

- query改写节点 + 两个检索节点
- 一个语义权重1关键词0，另一个关键词1语义权重0
- 两个节点绑定同一知识库
- 实测效果好了一点，但没好多少

#### 第二次尝试

- 两个检索节点绑定不同知识库
- 一个分段小，一个分段大
- 发现分段相差不多，但内容差异很大
- 还是无法找到最优检索策略

#### 第三次尝试

- 两个知识检索节点，绑定两个知识库
- 尝试不同检索策略：语义0.9关键词0.1 → 语义0.1关键词0.9
- 都试了一遍，召回率并没有比纯RAG提高多少

#### 关键突破

- 加了一个知识检索节点
- 三个知识检索 + 不同分段的知识库（小分段、大分段、Q&A、半结构化）
- 召回率达到八九十

### 未来方向

- 现在只要知识库里有的肯定能召回
- 但信息精度不够，偶尔不够准确，也不够完整
- 主要是有相同信息分散在不同分段
- **接下来要重点整理知识库的内容质量**

## 经验总结

### 硬件配置

- 本地部署需要较高配置
- 8G内存用bge-m3嵌入模型效率较低
- VLLM需要8核16G配置才能流畅运行
- 考虑升级配置或使用混合部署方案

### 平台选择

- Cherry Studio：入门级RAG平台，对新手友好
- dify：功能强大但配置要求高
- langchain：可塑性强但需要编程能力
- AnythingLLM：最熟悉的平台，可移动端使用
- 腾讯云ADP：云端搭建快但有试用额度限制
- 无影云电脑Ubuntu + dify：目前最优方案

### 嵌入模型

- BGE-M3：最优选中英文互检
- 英文数据多时建议用适合英文的嵌入模型
- 嵌入模型配置错误会导致检索失效

### 检索策略

- 纯RAG很难达到理想效果
- ChatFlow + 多知识检索节点效果更好
- 混合检索策略可提高召回率
- Reranker使用会极大提升检索效果

### 数据处理

- TXT文档编码要转换成不带BOM的UTF-8
- 带BOM的UTF-8编码向量化会有内容丢失
- 批量转换编码分两步：ANSI → 带BOM的UTF-8 → 不带BOM的UTF-8

### 心态建议

- RAG检索策略优化要花费搭建三倍的时间精力
- 要沉住气、耐心、尝试对比多种切块策略
- 失败不完全是一无所获，可能是以后要走的弯路先走了一遍
