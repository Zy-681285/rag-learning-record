
# 文档编码转换折腾记

> 从乱码深渊到柳暗花明

---

## 4月2日 - 折腾的开始

### 问题背景

忙活大半天就研究了怎么批量转换文档编码，按照豆包给的 PowerShell 命令，转化完的文档有概率内容都变成乱码。

找豆包要说法，它又给我 PowerShell 的命令，之前内容修改了，按照它给我的方法还是没办法把乱码变回原来的内容。还好云端有备份，而且也不是很难找的资源。

### 求助 DeepSeek

对豆包的能力有了一定的认识，我又去找了 DeepSeek，一开始还是给了我 PowerShell 的命令，尝试几个文档还是有可能出现乱码。

我就直接问他 PowerShell 命令转换方式是否都有一定概率会出现乱码，它才说这种方式适合英文字符，中文内容避免不了出现乱码的情况。

---

## 编码转换方案尝试

### 方案一：Python 脚本

后面又让我尝试用 Python 脚本来处理批量转换文档编码，居然也不行，跟部署 langchain 环境一样，显示电脑不支持。

### 方案二：VS Code 脚本

DeepSeek 给了我另一种方式，用 VS Code 脚本来操作，也是有点小复杂，最后运行成功，发现编码是转换过来了，但是内容全部空白了。

### 方案三：PowerShell 脚本

中间又尝试 iconv 来操作，没成，继续换下一个方案，用 PowerShell 脚本。

这种方式跟先前的 PowerShell 命令又不一样：

- **PowerShell 命令**：按住 Shift + 右键打开 PowerShell 的方式打开然后复制命令来执行
- **PowerShell 脚本**：先创建个文本，然后把脚本内容填好，保存再修改文本名称，双击打开就能执行

### 实际操作结果

实际操作才知道，不管是命令还是脚本结果一样：

- ANSI 编码直接转换成 UTF-8 会出现乱码
- 或者转化出的是带 BOM 的 UTF-8 编码

---

## 编码转换的真相

到了这一步我就明白了，编码批量转码，要分两步。但是这么操作效率不高。

又问 DeepSeek 有没有其他办法可以把 ANSI 编码转换成 UTF-8 编码，不带 BOM 不会乱码，不会清空内容的方法。

---

## 编码批量转换助手

### 初次使用

它给我推荐了个编码批量转换助手，我有点无语，有这玩意儿早不给我推荐？

我心想，不能什么都靠它，就按照它给我的名字去找。没想到一开始居然下载成别的流氓软件了，疑似是 360 的，点开程序居然是解压缩软件。

### 获取正规安装包

没辙，只得问它要这个软件的正规安装包链接。但是下载的时候系统检测到该安装包有病毒，没想太多 DeepSeek 推荐的无视风险直接下载。

下载完成免安装打开，界面很干净就跟 DeepSeek 描述的一样。测试了一下，没想到这玩意儿转换出来的只能是带 BOM 的 UTF-8 编码，事情又回到原点。

### 设置调整

我又去找 DeepSeek 怎么给我推荐的是这种软件，它说我是设置问题。按照它说的设置还是一样。

它又说，可能是版本比较旧的问题，然后给我这个软件的官方网站。到这我开始有点无语了，有官方网站，不早点给我发来。

### 新版本的问题

以为整个事情要解决的时候，发现还是没那么简单。新版本的编码批量转换助手默认也是转换出带 BOM 的 UTF-8 编码，如果想要转换成不带 BOM 的，要高级选项。

高级选项又点不了，官网又看了一下，原来这个还不是最新的。

又去下载最新的版本，没想到试用版只能单篇转换，批量转换还得付费。

---

## 深度思考

到了这一步，我开始反思：TXT 的 ANSI 编码一定要转成不带 BOM 的 UTF-8 编码吗？

答案是肯定并且暂时无解的。到目前为止，居然没有一个嵌入模型可以识别 ANSI 编码的 TXT 文档。

而且带 BOM 的 UTF-8 编码的文档向量化会存在前后文字小部分丢失。对于现在搭建的 RAG 来说无关紧要，但是这么小的问题都解决不了，我不甘心。

---

## 最终收获

此刻才明白，数据清洗包含的内容有多重要，而 TXT 文档是数据清洗当中相对比难度比较低的。

但是只花了半天就掌握了这一项技能，而且还学习到两种处理方式：

### 处理方式一：两步转换

1. 先转换成带有 BOM 的 UTF-8 编码
2. 再转化成不带 BOM 的 UTF-8 编码

### 处理方式二：付费工具

使用付费工具，更有效率的转换编码。

---

## 经验总结

### 编码转换要点

- ANSI 转 UTF-8 直接转换会有乱码风险
- 带 BOM 的 UTF-8 编码嵌入模型可以识别
- 向量化时带 BOM 编码可能有少量内容丢失
- 最优方案是两步转换或使用付费工具

### 工具选择建议

- PowerShell 命令：适合简单场景，中文可能乱码
- Python 脚本：需要环境支持，部分电脑不支持
- VS Code 脚本：操作复杂，可能内容清空
- 编码批量转换助手：界面友好，但新版本高级功能需付费

### 心态调整

不枉折腾半天，最终还是有了结果。晚点再测试纯 UTF-8 编码文档的准确率。
