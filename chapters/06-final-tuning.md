
# RAG本质思考与调优突破

---

## 4月30日 - RAG本质思考

### 核心三要素

RAG 本质上是在数据、Embedding 跟 Prompt 之间做一个平衡点，或者根据不同业务场景做某一方面的权衡。

### 数据质量

什么样的数据产出什么样的结果，这很重要。

需要考虑的问题：

- 同一文档内的数据是否协调？
- 是否准确？
- 另一文档的数据会不会有冲突？

在数以万计的字符内，找出重点并提炼，就像在一眼望不到边的沙漠寻找绿洲。

不一样的是，数据的提炼有工具可以使用，在沙漠寻找绿洲，则无计可施。

### Embedding 策略

整理好的数据又怎么 Embedding？是搭建一个合格的 RAG 需要思考的问题。

关键参数：

- **Chunk size 的大小**：直接影响召回率和准确率
- **重叠的大小**：影响内容连续性
- **嵌入模型选择**：至关重要

嵌入模型推荐：

| 场景 | 推荐模型 |
|------|---------|
| 中英文混合 | BGE-M3 |
| 英文为主 | 额外使用英文嵌入模型 |

虽然 BGE-M3 可以做到中英文互检，向量化的英文也可以通过中文检索出来，但是要考虑到准确率，如果英文数据不少，额外用个适合英文的嵌入模型会更好。

### Prompt 调优

生成部分的 Prompt，直接影响到生成的效果。

需要思考的问题：

- 幻觉率有多少？
- 准确率又有多少？
- Topk 要设置多少？
- 检索方式是向量检索还是全文检索？亦或是混合检索？

这没有标准答案，只能不断去尝试，用不同的 Prompt、Topk 去找一个平衡点。

### 关键工具

要是搭配 Reranker 使用，这会让检索效果极大提升。

### 我的理解

> RAG 是什么？依我拙见，是一个人站在三岔路口，每条路看起来都很好，但每条路都得尝试去走，走完之后要去开阔一条自己的路。

## 5月9日 - RAG 调优突破

### 可用 RAG 的标准

一个可用的 RAG 最终呈现的效果应当如下：

| 指标 | 标准 | 说明 |
|------|------|------|
| 召回率 | 20% 以内 | 问10个问题，2个没有回复，可接受 |
| 准确率 | 80% 以上 | 问10个问题，2个没答对，可接受 |
| 幻觉率 | 20% 以内 | 问10个问题，2个出现偏差，可接受 |
| 完整性 | 70% 以上 | 问10个问题，3个没答对或答对一半，可接受 |

### 纯 RAG 的局限

召回率其实很容易提升：

- 搭个 RAG 不导入任何信息
- 不加任何 Prompt
- 召回率肯定百分百

但回答真的是想要的吗？

召回率百分百了，要怎么去解决幻觉、准确率还有完整性？

对一个成熟的 RAG 来说，这几项是必须要平衡的。

但一个纯 RAG，不管再怎么调优，都很难达到理想的效果。除非数据不多，并且有固定的提问方式。

如果是这样的话，也没必要做一个 RAG，这跟直接在文档里面查找关键词有什么区别？

### ChatFlow 尝试

在纯 RAG 上面花了三周的时间，达不到理想的效果，只能尝试 ChatFlow。

#### 第一阶段：两个检索节点

- query 改写节点 + 两个检索节点
- 一个节点：语义权重 1，关键词 0
- 另一个节点：关键词 1，语义权重 0
- 两个节点绑定同一知识库

实测效果确实好多了，但没好多少，该召不回的还是召不回。

#### 第二阶段：不同知识库

后面想到能不能把两个检索节点分别绑定不同知识库，并尝试不同的检索策略。

一开始觉得是个可行的方案，两个不同的知识库，一个分段小，一个分段大。但后面发现：

- 同一知识库内分段确实相差不多
- 但是内容差异很大
- 还是无法找到最优的检索策略来达到可观的召回率

#### 第三阶段：不同检索策略

中间还尝试过两个知识检索节点，绑定两个知识库，采取不同的检索策略：

- 从语义 0.9、关键词 0.1
- 到语义 0.1、关键词 0.9
- 都一一试了个遍

召回率并没有比纯 RAG 提高多少。

花了半天时间才搞明白，之前的设想不是最优的方案。

#### 第四阶段：三个检索节点

后面实在没招了，又加一个知识检索节点。

没想到正是这一个无心之举，竟让这个 RAG 召回率达到现在的八九十。

当然也不是三个知识检索就能百分百召回，知识库除了大的分段跟小的分段，后面又添加了 Q&A 的知识库，还有同样内容半结构化的信息。

### 当前状态

做完以上这些，现在只要知识库里有的，肯定能召回。但是信息精度不够：

- 幻觉出现不多
- 但偶尔不够准确
- 也会不够完整

主要是有相同的信息，分散在不同的分段。这就会导致同样的信息，检索出来的内容：

- 有时候是在小分段
- 有时候是在大分段
- 有时候是问答类型的

### 未来方向

接下来要重点整理知识库的内容质量。

## 核心要点总结

### RAG 三要素平衡

```
数据  ←→  Embedding  ←→  Prompt
```

### 可用 RAG 标准

- 召回率：≤20%
- 准确率：≥80%
- 幻觉率：≤20%
- 完整性：≥70%

### ChatFlow 调优经验

1. 单知识库调优效果有限
2. 多知识库 + 多检索节点效果更好
3. 分段策略要多样化（小分段、大分段、Q&A、半结构化）
4. Reranker 能极大提升检索效果

### 未来重点

- 整理知识库的内容质量
- 解决信息精度问题
- 减少相同信息分散在不同分段的问题
