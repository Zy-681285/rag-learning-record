
# VLLM探索与RAG集成之路

---

## 4月25日 - 意外收获

### 跑步时的思考

有点意思，拉伸时间20来分钟，跑步不到50分钟。

听着小宇宙主 VLLM 主创团队采访，时不时飙个听不懂的英文，不过也听到些有价值的信息，AI 圈内人可能在模型发布中期就能体验得到，甚至能参与进去。

### VLLM团队的秘密

Deepseek 25年发布，早在24年7月份，VLLM 的主创团队都知道了。是 Deepseek 发布前就找 VLLM 的主创团队谈合作，共同参与对模型的部分调试以及 API 的对接。

### 团队背景

更想不到，VLLM 的初创团队大部分是来自伯克利的博士生跟教授，而且两名核心主创都是华人。不过这也很正常，毕竟 OpenAI 开发团队也有四，差不多 1/4 是华人。

### VLLM部署尝试

白天的时候想搭建 VLLM 环境来部署本地的大模型，最后因为云电脑内存不够没成功，又选用 ollama 尝试对接本地模型，虽然跑通了，但是响应速度不如 API 调用的大模型。

后面把 Ollama 以及本地的模型都删了，后续考虑升级配置，再尝试搭建 VLLM。

## 4月26日 - dify与钉钉集成

### 钉钉集成的愿景

自从把 dify 的 Rag 集成到钉钉之后，一连几天毫无进展。

先把已经搭建好的 RAG 迁移到云服务器，这样就可以 24 小时不间断在钉钉上测试使用。

### 阿里ECS碰壁

后面发现免费使用的云服务器只有两核两 GB，压根运行不了已经搭建好的 RAG。

后面想着做个轻量化的 RAG，还是用 dify 这个平台来搭。最后也没成，虽然 Docker 跟 dify 环境都搭建好了，但就是访问不了。

考虑到两核两 GB 的服务器，哪怕搭好了也不稳定，后期还要花很多时间维护，投入产出比不高，遂作罢。

### 工作流的尝试

中间又尝试把现有较为成熟的 RAG 应用到工作流，打算先从简单的文字流程化，再生成直观的图表。

捣鼓大半天没成，就几个节点，还是比较入门的工作流。虽然没跑起来，估计完成了有七八十的进度，暂时没心思继续，只得下次再尝试。

### RAG扩充的教训

前两天导入不同类型不同格式的数据，给 RAG 添砖加瓦，没成想，也出了差错，测试召回率极低，以为是文档嵌入的问题。

把知识库内容删了，重新向量化，发现还是召回不了，后面才想起来是搭工作流的时候改了 Prompt。

把 Prompt 改回原来的，测试了一下，召回率还是偏低。更换过的文档召回不了，没更换的文档是可以正常检索得到。

经过一系列排查，换了几次文档，跟不同切块大小，才发现可能是嵌入模型出了问题。

原来搭工作流的时候，需要用到 Rerank 重排序，就添加了 Qwen 的嵌入模型，导致的原有的模型失效了，又重新配置了 bge-m3 才恢复正常。

### 当前成果

现在有两个比较成熟的 RAG：

| RAG类型 | 内容特点 | 效果 |
|---------|---------|------|
| 小说散文型 | 纯中文，约100万字符 | 幻觉跟准确率相差很大 |
| 工作相关 | 跟现在工作相关 | 效果不错，幻觉可接受 |

### VLLM再次尝试

这两天尝试用 dify 接入本地的模型，用 Ollama 测试通过之后，听说 VLLM 对模型的掌控更好，特别是处理高并发的情况，更适用于企业级 RAG 的部署要求。

没有多想，就着手搭建 VLLM 的安装环境了，一开始以为跟 Ollama 一样简单。

### 配置升级

捣鼓了好半会才发现，要想用上 VLLM，8 核 16G 的配置才能流畅的运行。

为了用上 VLLM，只得被迫升级无影云的配置。VLLM 还没下载完成呢，光是安装依赖包都快占满磁盘了，因为这个差点又放弃了。

想到 VLLM 的含金量，又把云电脑的配置升级成 100G 的数据盘，今天终于搞定了 VLLM 的部署。

还是选用熟悉的 BGE-M3 来作为本地的嵌入模型。

### 意外的发现

VLLM 下载嵌入模型跟 Ollama 也大不同：

- Ollama：一条命令行十几二十分钟可能就搞定了
- VLLM：愣是两个小时才下载好 BGE-M3

在这个过程中也发现了 VLLM 用 GPU 来运行比 CPU 快很多，如果要长期用，还得升级配置。

不过目前只是为了走通这个流程，只要能把本地部署的嵌入模型跟大语言模型跟 dify 打通就行了。

### 最后的困难

没想到事情还不是那么简单，本地的嵌入模型跟 Dify 老是匹配不上，估计也花了快两个小时，最后也没成。

从 IP 地址、Docker 容器到网络端口，都检查了，模型是没问题的，但就是连接不上。

### 心态调整

一连串的失败，都有点自我怀疑了，后面冷静下来想，失败是事实，但也不完全是一无所获。

> 我只是把以后可能会走的弯路先走了一遍，所以接下来的路会更好走。

VLLM适合本地加载大语言模型

## 经验总结

### 工具选择

| 工具 | 适用场景 | 注意事项 |
|------|---------|---------|
| Ollama | 轻量级本地部署 | 下载快，配置简单 |
| VLLM | 企业级高并发 | 需要8核16G配置，下载慢 |
| Dify | 钉钉集成 | 需要更高配置 |

### 配置要求

- 免费云服务器（两核两 GB）无法运行 RAG
- VLLM 需要 8 核 16G 配置才能流畅运行
- GPU 比 CPU 运行速度快很多

### 常见问题

- 修改 Prompt 可能影响召回率
- 添加新嵌入模型可能导致原有模型失效
- 本地模型与云端服务连接可能存在问题

### 心态建议

失败不完全是一无所获，只是把以后可能走的弯路先走了一遍。
